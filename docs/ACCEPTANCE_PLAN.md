# 后续实现与验收计划（未执行）

仅在用户明确批准设计后开始；本文件不授权创建测试仓库、配置 ChatGPT、安装 Hook 或消费 API 预算。

## 分阶段

Phase 0 是环境、接口和复用调查；Phase 1 是协议/Schema/架构设计，本次到此停止。最终设计批准后先执行独立 [E0 真实 ChatGPT 写入实验](CHATGPT_WRITE_EXPERIMENT.md)，核实真实产品写入口与独立远程回读，不能以本地模拟替代。E0 不开发 CLI/Skill。根据结果确认范围后，Phase 2 才实现最小 CLI、初始化模板与全局 Skill；Phase 3 两项目可靠性；Phase 4 验证完整任务执行闭环及新会话恢复，不把早期写入口实验延后到这里。每阶段失败必须保留证据。

## 两个互不相关的测试项目

Project A：最小 Python 函数及测试；Project B：最小 C++ 程序及编译测试。各用独立 GitHub repo ID、任务和 outbox；仓库创建和公开性先由用户授权。任务 ID 即使都为 #1 也不碰撞。复用同一已安装 CLI 与 Skill，不修改同步源码；配置只改项目背景、仓库定位、审批者及验收命令。

| 场景 | 验收标准 | 必留证据 | 当前结果 |

测试结果必须区分 passed/failed/not_run/inconclusive。任何跨端项不能由 Codex 的本地模拟代替。

## 需要用户参与的最少事项

设计获批后：确认两个测试仓库的创建与公开性；在实际 ChatGPT 账号启用 GitHub 并选定测试仓库；检查真实工具列表及套餐/管理员策略；确认一条无害测试任务并发布批准。若测试自定义 MCP，需要用户有相应资格并完成 OAuth/管理员授权。不得要求在聊天粘贴令牌。

若 ChatGPT 无可用写入口，明确记录“尚未打通”，使用 GitHub 页面人工一次提交作为降级，不能把该降级包装成原生闭环。事件驱动、API 付费与常驻执行必须另行选择，不作为最小版本默认条件。

Git Ref 领取采用 [C01–C13 独立并发方案](GIT_REF_CONCURRENCY_PLAN.md)，当前全未执行；初期用真实请求验证，不把设计分支推送当作并发测试。
